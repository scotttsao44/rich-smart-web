## 3. 域名與 TLS（Caddyfile：`deploy/aliyun/Caddyfile`）
- **rich-smart.com.cn**：正式域名，已上線，蘇ICP備2026083440號-1；`www.rich-smart.com.cn` 301 → 正式域名。
- **sh.rich-smart.cn**：過渡域名（以及 sslip.io / nip.io 測試域名），仍可用。

## 4. 資料持久化
- **單機 JSON 檔案持久化**（compose 刻意設 `DATABASE_URL=""`，不用資料庫）。
- 資料目錄：容器內 `/data/caomi-cn`（`LOCAL_CN_DATA_DIR`），品牌媒體 `/data/caomi-brand-media`（`BRAND_PILOT_MEDIA_DIR`）。
- `seed-data/` 為初始種子資料。`lib/local-cn-*.ts` 為各類 JSON store。

## 5. 部署方式
1. 在其他機器（有 Node）執行 `npm run build`（`output: standalone`）。
2. 把 `.next/standalone`、`.next/static`、`public` 傳到伺服器 `/opt/caomi-cn`。
3. 伺服器上以 `Dockerfile.prebuilt`（node:20-alpine + poppler/tesseract OCR）打包映像，`docker compose up -d`。
- 原因：伺服器無 Node、可用記憶體僅約 1 GB，無法在伺服器上 `next build`。
- ⚠️ 伺服器原始碼缺少 `tsconfig.json`、`next.config.js`、tailwind/postcss 設定與 `scripts/`，無法單獨在此重建；建置時需搭配建置機上的完整原始碼。

## 7. MQTT（`/opt/caomi-mqtt`）
- Mosquitto 2，`allow_anonymous false`，帳密檔 `config/passwd` + ACL `config/acl`（passwd、certs 為機密，不進 git）。
- 埠：**8883 TLS**（憑證＝Caddy 的 rich-smart.com.cn Let's Encrypt 憑證，由 `sync-cert.sh` 每日 04:17 cron 同步）；**1883 明文**（僅韌體試點用，試點後關閉）。
- Topic：`richsmart/dev/{設備編號}/cmd`（平台→設備）、`/ack`（設備回覆）、`/status`（上下線，LWT retained）、`/event`（設備事件）。
- 帳號：`platform`（richsmart/#）、`dev-{id}`（僅自己的 topic，用 `add-device.sh` 建立）、`factory-test`（工廠測試）。
- 測試腳本：`mqtt_e2e_test.sh`（密碼由環境變數傳入）。

## 8. 回滾
- 程式碼：`git log` → `git checkout <commit>`（或 `git revert`）。
- 映像標籤：`caomi-cn-web:rollback-pre-icp1-20261030`、`rollback-pre-icp-20261030`、`pre-native-202610261437`。回滾＝把要用的標籤改標為 `latest` 後 `docker compose up -d caomi-web`（須事先獲准）。
- 備份：`/opt/caomi-cn-backups/`（env、Caddyfile、`.next` 與原始碼 tgz）；伺服器上 `.next.old-icp1/` 為上一版建置產物。
